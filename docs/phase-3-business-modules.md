## Implemented behavior

- Independent customer, supplier, lender and borrower roles; durable source drafts; invoices, bills, immediate receipts, tax lines and credit notes. Historical roles cannot be removed when financial records depend on them. Party statements calculate role-separated balances on the server.
- Exact partial/multiple payment allocation, credited-funds refunds, separate settlement fees, customer/vendor advances and applications. Refunds require the original credit and paid allocation. Loans keep principal, interest and fees separate and reject over-repayment.
- Bank CSV mapping, preview, history and immutable raw rows. File/source deduplication preserves legitimate identical transactions. Date, signed amount, account, state and descriptor filters support review. Categorize/split, exclude, bounded source-journal matching, transfers and card settlements require explicit choices. Category corrections append adjustments without changing original bank movement.
- Same-day paired transfers post once. A missing side uses explicitly approved clearing. A later side posts against clearing and links to the earlier source without editing the finalized original. Unique peer claims prevent duplicate consumption; separate dates retain separate accounting events.
- Versioned tenant rules with sample preview, approval, pause and rollback. Suggestions remain deterministic, approval-only and abstain. No external enrichment or autoposting is asserted.
- Allocation-based cash/accrual financial reports, aging, loan/control and tax-support tie-outs, trends, immutable report history and authorized snapshot answers. Imported financial baselines support historical tax tie-outs. Thirteen-week forecasts disclose due-date assumptions, missing probability bands and unsupported obligations.
- Private encrypted evidence, hash and normalized reviewed supplier/date/currency/total duplicate candidates, ClamAV quarantine, leased retries and reasoned failed-job replay. Original text stays immutable; human annotations and reviewed identity revisions remain separate. English PDF/PNG/JPEG extraction returns source regions and engine/model fingerprints. Unsupported HEIC/CSV/XLSX automatic extraction retains scanned manual review. Extraction never posts entries or merges originals.
- In-app reminders/notifications/preferences; settlement/dispute recheck; audit, job, usage, consent and privacy histories. Scoped MFA personal-data export and retention-review requests do not claim automatic deletion. Beneficiary proposals are encrypted, masked, idempotent and held; no payment execution or ownership-verification claim.
- Scoped membership administration preserves an active owner. Close requires independent preparer/reviewer and approved mandatory tasks; readiness discloses its checks and limitations.
- Formula-safe journal CSV and an offline evidence ZIP with relative links, source/report/statement/rule/identity/opening-approval history, original hashes and Ed25519-signed manifest. Durable encrypted 24-hour snapshots support authenticated resumable byte ranges and ETag checks. Artifacts are private to the creator, capped at 10 MiB each and three live snapshots per member/business. Larger selections require narrower dates.
- Reviewed chart/journal/trade/loan CSV import, row errors, cutover date, exact trial baseline and parallel comparison. Financial child operations commit atomically. The user-approved `opening` mode now supports accountant-reviewed residual AR/AP and loan balances against explicit equity without recreating historic transactions. See [the opening contract](contracts/opening-balances.md).

## Consistency and local limits

Business GET transactions take a shared row lock; financial writers take the exclusive lock. Counter transactions use a separate two-connection pool to avoid nested admission-pool starvation. Default budget is twelve database connections per API process: five retained, five overflow and two counters. Statement/lock limits remain bounded. The configurable idle-transaction timeout defaults to 15 seconds: five seconds terminated a login during password verification under instrumented test load. Password verification still occupies a transaction; measure and isolate that cost before scaling authentication.

Pilot limits include 500 bank rows/import (or the lower trial limit), 100 migration rows, 25 financial operations/migration batch, 10,000 source operations/business, 200 evidence documents, 100 MiB aggregate evidence, 25 MiB/file, ten PDF pages, sixteen megapixels/image, twenty thousand extracted words, 120 user/business requests per minute and 600 business requests per minute. Exports cap journals, files and archive bytes. Read/export/privacy access survives read-only trial status; no automatic paid upgrade exists. These are protective caps, not measured user capacity.

See [ADR-011](architecture/ADR-011-phase-3-sources-and-local-extraction.md) and [ADR-012](architecture/ADR-012-reviewed-opening-balances.md). Migrations `0006`–`0018` add source/workspace/evidence/import/transfer/opening invariants. The existing development database volume and data were preserved.

## Local setup and recovery

1. From `backend`, run `uv sync --locked --all-groups` and `uv run python -m ledgerpilot.local_setup prepare`. Missing local secrets are generated privately. Initialized keys are preserved; unsafe replacement is refused.
2. Set `OCR_ENABLED=true` in the ignored root environment. The helper supplies `EVIDENCE_ENCRYPTION_KEY`, `EXPORT_SIGNING_PRIVATE_KEY` and `OCR_SERVICE_TOKEN`. Preserve existing database, MFA and session keys. Never paste secrets into chat.
3. From the root, start the existing PostgreSQL/SMTP services and run `docker compose -f docker-compose.documents.yml up -d --build --wait --wait-timeout 300`. ClamAV and OCR bind loopback. OCR runs as UID 10001 with read-only root, bounded temporary storage, dropped capabilities and resource limits; it receives no database/authentication/encryption keys. Combined document-container RAM ceilings total 6 GiB. The local bridge does not enforce outbound denial; deployment must add network restrictions.
4. From `backend`, apply `uv run alembic upgrade head`; readiness expects `0020`. Never reset the existing volume to upgrade.
5. Invoke one scoped job with `uv run python -m ledgerpilot.documents.worker --actor USER_UUID --business BUSINESS_UUID`, using an existing authorized member. This is an operator command, not public impersonation. Inspect `/jobs`; retries back off and eventually fail. After fixing a dependency, owner/accountant may replay a failed quarantined job with a reason. Infected files do not become clean through replay.
6. Back up private originals and encryption/signing keys with controlled access. Never replace initialized keys to resolve availability errors. Financial schema repair uses forward migrations. Production backup/restore, SQS delivery, observability, scaling, browser HTTPS acceptance and cloud deployment retain their planned phase gates.
