# Security checklist audit — 3 November 2026

The 20 items in the supplied image were checked against the current P1 implementation. This is an engineering review with local regression evidence, not a penetration-test certificate or a statement that the deployed system is secure. Phase 9/10 infrastructure and live acceptance gates remain separate.

## Repairs implemented

- API security headers now wrap CORS and application middleware, including preflight, validation/CSRF rejections, normal responses and unexpected-error responses. They add anti-framing, restrictive API CSP, no-referrer, permissions restrictions, no-store and nosniff. Hosted HTTPS/HSTS handling covers preflight as well, retaining only the deliberate private health-probe exception. Raw forwarding headers cannot satisfy HTTPS.
- Production web builds inject CSP before scripts. Script execution is limited to local assets and the official Google GIS client; connections are limited to the current origin, the explicitly configured public API origin and GIS. Objects and base URLs are disabled. Vercel/preview headers deny framing; Vercel adds HSTS and permissions restrictions. Inline styles remain allowed for existing layout/GIS behavior; inline scripts and eval are not allowed. Local development retains its HMR and Google HTTP-loopback behavior.
- All owned-session routes now share a durable per-user admission limit of 240 requests per minute, including routes outside a business workspace. Existing auth IP/email and business/user limits remain. Upload admission and its handler consume one user admission, despite independently rechecking identity. Limits commit outside the business transaction and return 429/Retry-After rather than silently bypassing a failed limiter.
- Updated `cryptography` 47.0.0 → 50.0.2, pytest 8.4.2 → 9.2.0 and pytest-asyncio 0.26.0 → 1.4.1.post1. Recorded lockfiles and explicit async-fixture scope. Previous-version Fernet ciphertext decrypts successfully with the updated library; no application encryption key, password, JWT format or schema changed.
- Malformed non-ASCII OCR bearer headers now fail with 401 instead of raising a comparison exception. The local OCR image was rebuilt with the patched dependencies/source and reached healthy status.
- The AWS deployment helper now rejects a runtime environment file unless it is root-owned with mode 600, before cloud commands. New and rollback API containers drop capabilities, prohibit privilege escalation and limit PIDs. The guard was executed in an isolated container using a synthetic file; no AWS deployment was performed.
- CI now audits all Python dependencies, all web runtime dependencies and high/critical web development-tool advisories. Audit JSON is retained with verification artifacts. The known moderate development-tool advisory below is explicitly open.

## Verdict for every image item

1. **Row-level security — verified locally.** Actual tenant tables have RLS enabled and forced. The runtime role cannot bypass RLS or act as a superuser. Identity/membership checks bind transaction-local tenant scope. PostgreSQL and API cross-tenant regressions verify rejection.
2. **Auth on every API route — verified with explicit exceptions.** An inventory test requires owned cookie authentication on every private OpenAPI operation. Public registration/login/recovery/verification/Google-proof initiation, CSRF/config and minimal health endpoints are deliberate exceptions. Refresh authenticates its stored refresh token rather than requiring a still-valid access token. Privileged business actions require server-side membership/permissions and MFA.
3. **Never trust the frontend — verified locally.** Pydantic schemas reject undeclared fields; the API and PostgreSQL enforce permissions, currency precision, balances, dates, period locks, immutability and idempotency. Client-side visibility or totals cannot grant authority.
4. **Rate limiting — repaired and tested.** Auth IP/email, global authenticated user and workspace/user limits use durable shared PostgreSQL counters. Production edge limits for unauthenticated floods and resource-intensive traffic still require proxy/network configuration and load verification. There are no public API keys in current P1.
5. **Sanitize input — verified for implemented paths.** Use strict type/length/range validation plus context-specific output encoding, not destructive rewriting of financial evidence. React renders text, exports escape HTML and spreadsheet-formula cells, and user input is never treated as executable markup/SQL. The new browser test proves CSP blocks an injected inline script.
6. **Parameterized queries — verified locally.** SQLAlchemy/bound SQL handle user values. Administrative identifiers are quoted by the database driver's identifier APIs. Transaction rollback and safe database-error envelopes are covered by the preceding database audit.
7. **Lock down CORS — verified locally.** Origins must be explicit, with no wildcard or URL credentials/path. Methods and headers are bounded. Tests verify allowed and denied preflight; CSRF/Origin checks independently protect writes. CORS is not used as authentication.
8. **HTTPS everywhere — implemented; deployment verification pending.** Hosted API HTTP requests are rejected before bodies/preflight; HTTPS gets HSTS. Auth cookies are Secure/HttpOnly with explicit SameSite. Hosted PostgreSQL requires verified TLS, and enabled hosted SMTP requires TLS. Private health probes and local same-origin loopback are documented exceptions. Actual certificates, trusted proxy peers, public ingress and Vercel/AWS behavior must be verified in Phase 9/10.
9. **Verify webhook signatures — not applicable to current P1.** No inbound webhook route exists. This is not marked as a verified webhook implementation. Any future connector must validate raw-body signatures, timestamps/replay, event idempotency and mapped tenant authority before activation; it must not receive a blanket CSRF/auth bypass.
10. **No commands from chat text — verified for the current product assistant.** It accepts an allowlisted report metric and returns an authorized report lookup with `actions_executed=false`. It has no arbitrary prompt-to-SQL, shell, migration, payment or posting executor. This refers to the product, not authorized developer tooling used to maintain the repository.
11. **Debug mode off in production — verified configuration.** FastAPI debug is false, hosted Swagger/OpenAPI/Redoc routes are unavailable, and errors redact exception/SQL details. Local Swagger has a narrowly documented CSP exception for its existing development assets.
12. **Claude security review — not a technical security control.** This audit and its tests were performed; no separate Claude service or independent external penetration test was run. A model/vendor label cannot replace the controls or prove absence of vulnerabilities.
13. **Private storage buckets — local adapter verified; cloud gate pending.** Current originals are encrypted private files with generated keys, containment checks, restrictive Linux modes, quarantine and authorized attachment-only downloads. There is no cloud bucket to audit yet. Cloud public-access blocking, IAM, encryption/retention policy and deployed volume/host ACLs require actual infrastructure verification before cloud storage is enabled.
14. **Lock dangerous tools — verified for current scope.** No generic execution/admin tool endpoint exists. OCR uses fixed argument arrays, timeouts, a private bearer token and an unprivileged, read-only, resource-limited container without financial credentials or Docker socket. Its ports are loopback-published. Production egress restrictions remain an infrastructure gate; the local Docker Desktop bridge is not claimed to be an outbound firewall.
15. **Hide admin pages properly — server authorization verified.** URL secrecy is not a control. Workspace administration/settings are backed by owned identity, active membership, role/permission and MFA checks. Changing client-side routes or role fields cannot grant administrative access.
16. **Update vulnerable packages — partially closed.** Python and web runtime audits now report zero known advisories. Three moderate dev-tool findings remain for one minimatch advisory in the OpenAPI generator chain; see below. Container OS/platform scans and live image promotion remain deployment checks.
17. **Security headers — repaired and locally verified.** API success/rejection/error/CORS responses and production browser script enforcement are tested. The configured Vercel headers still require verification on the deployed hostname. CSP is defense in depth, not a substitute for server validation or safe rendering.
18. **Check file upload types — verified for supported pilot paths.** Auth/role checks precede upload buffering; size/type/extension checks and generated storage keys apply. Originals remain quarantined until a positive ClamAV result. Only supported inputs reach bounded OCR; unsupported HEIC/XLSX inputs do not become executable content or unrestricted parsers. Downloads use attachment/octet-stream and nosniff, not inline user HTML.
19. **Stop IDOR bugs — verified on tested routes.** Membership and tenant/object ownership are checked on the server and reinforced by RLS, including evidence, reports, exports and newly batched queries. Forbidden/unshared records do not become accessible by changing UUIDs. This is regression evidence, not a mathematical guarantee for every future endpoint.
20. **Log admin actions — verified locally.** Security/business changes write scoped audit events in the business transaction. Runtime DELETE of audit history is denied. Logs/errors do not contain credentials, tokens or private request bodies. Production collection, alert delivery, retention and incident response still need operational verification.

## Open dependency finding

`GHSA-g3hv-75wg-m249` affects minimatch below 11.0.1. The supported installed chain is `openapi-typescript 7.13.0 → @redocly/openapi-core 1.34.22 → minimatch 5.1.9`. npm reports three affected development packages for this one underlying advisory; none is a browser/runtime dependency. The generator currently consumes the reviewed repository schema, not uploads or a public generation endpoint.

A forced minimatch 11 override changes its callable CommonJS API; Redocly 1 calls the old callable export. npm's suggested openapi-typescript 6.7.6 change is a breaking downgrade. A forced Redocly major override also falls outside the generator's declared dependency contract. These were not silently forced or represented as patched. Track a compatible upstream update or a separately tested generator migration, and review this open finding by **3 December 2026**. Do not expose this tooling to untrusted schema/config inputs in the meantime. CI blocks every reported runtime issue and high/critical development issue; moderate development findings remain visible in its full report.
